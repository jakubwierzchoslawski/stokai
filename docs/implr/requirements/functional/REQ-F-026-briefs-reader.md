# REQ-F-??? — Briefs and Reports Reader

## Domain Context
The Briefs reader displays Morning Briefs, Watchlist Scans, Earnings Briefs, and Event Deep-Dive memos. Each brief shows per-report confidence and supports user feedback (thumbs up/down/edit) that routes to Layer 4 memory and the admin audit loop.

## Summary
The system must provide a briefs reader that displays confidence level per brief and captures user feedback (thumbs up/down/edit) that is immediately routed to the Layer 4 user feedback memory table and surfaced in the admin audit loop.

## Detailed Description
As specified in ui-design-digest.md business rule 33, every report/brief displays confidence level and sample size inline (transparency is a product feature, not fine print). User feedback controls (thumbs up/down/edit) are present on every report.

Briefs list includes: Morning Briefs, Watchlist Scans, Earnings Briefs, Event Deep-Dives. Each entry shows: type, date, headline, confidence, delivery status.

Feedback routing: immediately writes user_feedback row to Layer 4 with decision_ref pointing to workflow_run_id. The admin AI audit console shows feedback signals alongside originating AI output. An edit correction triggers a golden dataset candidate proposal in the admin panel.

## Desired Outcome
Users can read AI-generated briefs in a confidence-transparent interface and provide explicit feedback that directly improves future AI output quality through the continuous improvement loop.

## Acceptance Criteria
- [ ] AC-001: Given a user opens a Morning Brief, the confidence score is displayed prominently within the brief header, not in a footnote or tooltip.
- [ ] AC-002: Given a user clicks thumbs down, a user_feedback row is written to Layer 4 with feedback_type=thumbs_down and the brief's workflow_run_id as decision_ref, without requiring any admin action.
- [ ] AC-003: Given a user provides an edit correction, the user_feedback row includes the correction text and the admin AI audit console surfaces a golden dataset candidate proposal for that correction.
- [ ] AC-004: Given a brief was generated with sample_size < 5, the disclaimer is visible in the brief body inline with the recommendation.
- [ ] AC-005: Given a user navigates to the Briefs section, all past briefs are listed in reverse chronological order with type, date, and confidence visible.

## Out of Scope
- In-brief trading actions
- Brief sharing or export to PDF in MVP

## Data Models
```
Brief (DB row and frontend view):
  brief_id: UUID
  type: enum(morning_brief, watchlist_scan, earnings_brief, event_deep_dive)
  content: text (HTML)
  confidence: float
  sample_size: int
  low_sample: bool
  sent_at: timestamp

user_feedback (from reader):
  feedback_type: enum(thumbs_up, thumbs_down, edit)
  correction: text | null
  decision_ref: UUID
  source: reader
  timestamp: timestamp
```

## Process Sequence
1. User navigates to Briefs section
2. Briefs list loaded with type, date, confidence
3. User opens a brief — full HTML content rendered with confidence visible
4. User clicks feedback control (thumbs up/down/edit)
5. user_feedback row written to Layer 4 immediately
6. If edit: golden dataset candidate proposed in admin panel
